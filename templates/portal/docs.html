QUICKSTART

Create your first checkout session

To begin, make a POST request from your server to our `checkout/sessions` endpoint. You'll need an API key from your merchant workspace. Every write request should also include a unique `Idempotency-Key` to prevent duplicate transactions.

POST /api/v1/checkout/sessions/ 
curl -X POST https://api.amatopay.bi/api/v1/checkout/sessions/ \
            -H "Authorization: Bearer sk_••••" \
            -H "Idempotency-Key: order-1001" \
            -H "Content-Type: application/json" \
            -d '{
                "order_number": "ORDER-1001",
                "description": "Online purchase",
                "amount": "50000.00",
                "currency": "BIF",
                "payer_alias": "+25779000000",
                "return_url": "https://merchant.bi/payment/result"
            }'

AmatoPay will respond with a session object containing a unique ID and a `checkout_url`.

PAYMENT LIFECYCLE

One traceable flow from checkout to payout

  1. 1Verify CustomerCustomer identity is verified to ensure secure and compliant transactions.
  2. 2Create SessionYour server sends order, customer, and amount details to AmatoPay.
  3. 3Customer PaysRedirect the customer to the checkout_url where AmatoPay handles the secure payment flow.
  4. 4Funds are ProtectedPaid funds are held separately pending delivery confirmation, building trust with your customer.
  5. 5Settlement CompletesOnce delivery is confirmed, released net funds are paid out to your verified merchant account.
◇

SECURITY

Design for verification, not assumptions.

Never treat the browser `return_url` as proof of payment. The customer may have closed the browser before payment was complete. Always verify the payment status using the API or a signed webhook before fulfilling an order.

PROTECTED FUNDS

Delivery-aware settlement

AmatoPay tracks fiduciary holds, delivery confirmation, operational reviews, refunds, and final settlement as separate auditable states. Domestic transactions use a four-business-day standard protection window; international transactions use fourteen calendar days, subject to compliance review.
