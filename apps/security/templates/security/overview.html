A portable Security Center with its own database.

This package groups request logging, alert detection, IP blocking, endpoint policy, staff-only access, dashboard actions, and block pages inside the Django `security` app. Security events can live in `security.sqlite3`, separate from business data.

Detection

Threat signals

Brute-force behavior, request rate spikes, scanning paths, suspicious user agents, injection probes, path traversal, and admin probing can become security alerts.

Tracking

Request visibility

Every non-static request is recorded with IP address, method, path, query string, response code, response time, user agent, referer, API flag, and merchant id when available.

Response

Block and resolve

Staff users can block IP addresses, unblock them, resolve one alert, or resolve all alerts from the dashboard without leaving the security console.

Database

Isolated storage

`RequestLog`, `SecurityAlert`, and `BlockedIP` are routed to the `security` database alias, backed by `security.sqlite3` in this project.

Copy to another project

Integration checklist

Add `security.apps.SecurityConfig` to `INSTALLED_APPS`.
Add the security middleware stack after authentication middleware.
Edit `security/endpoints.yaml` for project-specific skip, rate, and circuit endpoints.
Add `DATABASE_ROUTERS = ["security.db_router.SecurityDatabaseRouter"]`.
Add a `security` database alias, for example `BASE_DIR / "security.sqlite3"`.
Include `path("security/", include("security.urls"))` in the project URLs.
Run `python manage.py migrate --database=security security` and create a staff user in the main DB.
Templates

Self-contained UI

Login, dashboard, blocked-IP, and overview templates live inside `security/templates/security/`, so the app carries its interface with it.
